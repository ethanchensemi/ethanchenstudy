名詞是什麼
步驟 1 至 3 · 文字轉向量
Token約四個字元的文字片段；常見字是一個 token，罕見字則要好幾個
詞彙表模型認得的固定 token 清單，視模型而定32,000 到 256,000 個
斷詞器把文字切成 token 並轉成 Token ID 的小程式
Token IDtoken 在詞彙表中的編號
向量每個 Token ID 變成的一串數字，每一層都會讀取並更新它
步驟 4 · Transformer
Transformer模型本身：一疊相同的層，其中學到的數字（權重）承載了它的知識
層堆疊中的一個區塊，依序做兩件事：先 Attention，再 Feed-Forward
Attention從相關的先前 token 匯入資訊，藉此取得上下文
Feed-Forward獨立轉換每個 token 的向量，藉此取出知識
KV Cache儲存先前 token 的 Key 與 Value，不必重新計算
步驟 5 與 6 · 選出 Token
分數與機率詞彙表中每個 token 都會得到分數，再轉換成總和為一的機率
抽樣依機率加權隨機抽出下一個 token
溫度抽樣的隨機程度；設為 0 時永遠選機率最高的 token
步驟 7 至 9 · 迴圈
運算次序完整跑過所有層一次，產生一個 token
Prefill第一次運算，一口氣讀完整個問題，決定第一個字要等多久
Decode之後每產生一個 token 跑一次，速度由記憶體頻寬決定
結束 Token代表「結束」的特殊 token，由模型在訓練中學會
長度上限輸出長度上限，若始終沒出現結束 token 就由它中止迴圈

C2

數值格式與張量核心

以更少位元儲存每個數字如何加快晶片運算並節省記憶體，以及準確度上的代價。

重點說明
張量核心GPU 中一次完成一小塊矩陣乘法、而非逐個數字計算的單元；B4 的矩陣運算幾乎都由它負責
數值格式FP 代表浮點數、INT 代表整數，後面的數字是每個數值的位元數；BF16 是 brain float 的縮寫，為 Google 設計的 16 位元格式
範圍與精度指數位元決定數值能多大或多小，尾數位元決定保留幾位有效數字；BF16 保有 32 位元數值的範圍，犧牲的是精度
速度位元每減半，張量核心的運算量約增加一倍，因為相同晶片面積與功耗可容納兩倍的乘法器，所以 FP8 約為 BF16 的 2 倍、FP4 約為 4 倍
記憶體每個權重在 BF16 占 2 位元組、FP8 占 1 位元組、FP4 占 0.5 位元組，所以 70B 模型約需 140、70 或 35 GB，每次 Decode 從 HBM 讀取的資料量也等比例減少
準確度位元越少，捨入越粗略，因此業界以較高精度保存累加結果，並讓每 16 或 32 個數值共用一個縮放係數；訓練大多仍使用 BF16 與 FP8
世代演進每一代加速器都在硬體上支援更小的格式，所以模型能用的最小格式取決於它所在的晶片
解讀規格帳面峰值常以最小格式並計入稀疏性，數字會加倍，因此比較晶片時應使用相同格式的非稀疏數值
